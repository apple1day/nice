# 本地播放列表：按钮切换与大视频库性能

## 当前操作

上下滑切换、相邻页面预览、跟手位移、分页动画及延迟切换回调已从播放器移除。
画面轻点仍然显示/隐藏控制栏，但上下拖动画面不再换片。

- 竖屏：进度条上方提供「上一个 / 播放列表 / 下一个」。
- 横屏：沿用底部的上一个、下一个按钮。
- 播放列表弹层仍可点选任意条目，VoiceOver 的上下条操作保留。
- 首尾按钮禁用，不循环；下一项文件缺失或无效时，按顺序尝试下一个候选。
- 收藏按钮仍在删除旁边，星标同时显示在本地列表和播放列表中。

## 不在播放/拖动路径中扫描文件

旧的相邻预览调用 `store.localPlaylistRecords`，在视图刷新和手势回调中遍历全部已下载视频，
逐个检查文件属性。当前播放列表改从内存中的已完成下载记录建立，缓存条目、序号、邻居和当前收藏/待删除状态。
只有下载记录变化时才更新这些元数据缓存（不读取视频文件）；播放时间回调不会重建列表。

进度条的临时位置放在独立 `PlaybackProgressView` 中。拖动只改变这个小视图的显示位置，
松手向当前引擎提交一次 seek；不会读取其他文件、切换媒体或重建播放器。
相同的播放状态、时长和标志不再反复发布给 SwiftUI。

文件验证没有全部移除：

1. 用户明确打开、切到上一条/下一条或点选列表项目时，验证目标本地文件。
2. 遇到缺失/无效的相邻文件，仅依序检查候选直到找到一个可用文件，不预检查其余项目。
3. 下载完成的响应、大小/错误文本检查，删除事务和活动播放文件保护全部保留。
4. 启动及回到前台原有的存储对账仍保留，本次不修改 `VideoStore`；它不是进度条变化触发的检查。

因此这次去掉的是播放/拖动路径的整库重复检查，不是跳过下载完整性或路径安全检查。
如果文件在缓存建立后被外部移除，条目可能暂时保留，点开时会明确报错或在前后切换时跳过，不会回退到网络播放。

## 数据与删除行为不变

播放器「删除」只加入待删除列表，没有数量上限，不自动删除。必须回到本地列表顶部执行一键删除并确认。
收藏不影响待删除状态；本次不修改下载索引格式、视频文件、播放位置、Bundle Identifier、签名或 VLC 版本。
服务器远程删除及本地批量删除保持原逻辑。
