# 大视频库列表、观看标记与最新下载排序

## 界面

本地列表顶部右侧为「删除待删除」「选择」，文案不附带数量。待删除数量在列表摘要中显示。
删除仍需确认，仅处理确认快照中的本机待删除记录；重新下载的同 ID 新批次、撤销标记及正在播放的文件受保护。
不受搜索筛选影响，不删除服务器文件。长按某个待删除条目可撤销标记；原本地多选删除及下载任务清空保留。

每行显示「已观看 / 未观看」、收藏星标和待删除标记。
已观看表示播放器已进入 playing 且有视频输出，不等于看完。仅打开、失败、单纯拖进度、暂停后的迟到事件不计。
观看标记只保存一次，不随每个时间回调写整个索引。升级、断网、重启保留；重下同一内容继承标记和收藏。
旧版没有观看字段，升级仅把仍有正数播放进度的记录补标。已看完但旧进度被清除的历史不能凭空恢复。

新下载按实际完成时间 downloadedAt 倒序，最后完成的在最上面（不是加入任务队列的时间）。
旧记录没有完成时间，使用原下载索引顺序倒序，不读取每个文件的修改时间，也不伪造下载时间。
播放器前后切换顺序与打开时的本地列表一致；播放期间不因收藏/已观看或新下载重排当前播放列表。

## 性能改动

- LocalLibraryModel 只订阅下载记录、恢复状态和删除提示，不订阅高频下载进度。
- 预先生成行数据、大小文本、总大小、搜索结果和待删除列表，行视图只读本行数据。
- 列表行使用稳定 ID 和 Equatable 标签，取消逐行扫描全部记录及滚动时反复格式化大小。
- VideoStore 缓存 ID 查询、已完成/未完成、待删除和总大小；服务器匹配记录时每条仅计算一次 ID，不再在循环内反复 SHA256。
- App 实际入口改为 LibraryRootView，仅观察播放展示/错误状态，不因进度回调整体刷新，也不在回到前台时扫描媒体库。
- 冷启动先读小体积索引和必要的删除事务恢复，不逐个校验所有已完成文件；只检查未完成下载以恢复中断任务。
- 显式播放或切换才校验目标，失败后只对该 ID 对账。完整性校验、路径限制和删除事务没有移除。
- 原来的上下滑分页仍关闭，播放中的 seek 不扫描其他视频。本次未更换 VLC 解码器。

旧 RootView / UpdatedRootView 属于兼容旧入口，当前 NiceVideosApp 使用 LibraryRootView。
未完成任务恢复仍可能做少量文件检查；已完成条目被外部删除时允许暂时显示，点开时提示，不会回退联网。

真机验收：打开/滚动/搜索原有约300个视频；快速切回前台；顶部确认删除和撤销标记；

确认收藏、原下载文件、前后切换、拖进度和远程删除仍正常。
