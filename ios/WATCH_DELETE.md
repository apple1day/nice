# v1.1 — 边看边标记，保留最近 3 个待删除视频

## 使用

播放器画面正中间新增「删除」按钮。点击是加入本机待删除队列，不会立即删除当前文件，不会停止当前播放或自动跳到下一个视频。已加入后显示「已待删除」和队列数量，可以点「撤销待删除」。重复点击不会重复加入或改变顺序。

默认上限固定为 3（VideoStore.deletionQueueLimit），不是加入第 3 个就删除，而是加入第 4 个才淘汰最早的一项：

| 操作 | 队列（从最早到最近） | 实际删除的手机副本 |
|---|---|---|
| 标记 A | A | 无 |
| 标记 B | A、B | 无 |
| 标记 C | A、B、C | 无 |
| 标记 D | B、C、D | A |
| 标记 E | C、D、E | B |
| 一键删除所有待删除视频 | 空 | C、D、E |

「本地视频」和「服务器视频」两个列表均新增待删除区域：数量、可展开的队列、逐项撤销，以及「一键删除所有待删除视频」。一键清理会确认一次，确认后删除队列内手机副本；没有待删除项目时按钮禁用。正常列表上的对应项目也会标记待删除。

**只删除手机内的文件与本机索引、进度，不调用服务器 DELETE API，不删除服务器原视频。** 服务器列表仍然可以显示原视频和重新下载按钮。批量操作针对本机全部待删除项（包含不同服务器），不受搜索或当前服务器过滤影响；确认框会明确这个范围。未标记的视频不受影响。

「待删除」期间文件仍占手机空间，仍可播放和撤销；真正删除之后不可通过撤销恢复，需要从服务器重新下载。本版本不提供自动播放下一集、自动退出播放器或阈值设置界面。

## 数据与异常行为

队列顺序保存在 v1 下载索引每条记录的可选字段 pendingDeletionOrder，和下载记录同一次原子写入；旧索引没有这个字段时默认为未标记。App 重启、离线启动、更换服务器不会清空队列，不会在启动时自动淘汰还保留的三项。

加入第 4 项时，先把最早文件移动到 Application Support/NiceVideos/RemovalStaging，再原子写入淘汰旧记录并加入新标记后的下载索引，最后清除暂存文件。索引写入失败会移回原文件，内存队列不更新；物理删除失败会明确提示，不伪装成释放空间成功。批量删除逐项提交，失败项仍在队列中供重试。

重启时根据已提交索引恢复中断事务：索引仍引用的暂存文件移回 Media；索引已去掉的文件完成清理并移除播放位置。索引损坏/缺失、存在目录/符号链接/未知文件或冲突副本时保留文件并报错，不做猜测性删除。开始同 ID 的新下载之前也要完成暂存清理，避免旧文件被当作新下载复活。

播放器持有文件的保护状态，直到 PlaybackModel.close() 停止 VLC 并保存进度以后才释放。正在播放的文件不会被清理，覆盖层刚关闭但引擎还没关闭时也不会删除。正常使用是在 D 的播放器中标记 D、淘汰已经关闭的 A，不影响 D 的画面和声音。遇到异常调用想删除正在播放的最早项时，保留原队列且拒绝加入第 4 项，提示先关闭再重试。
