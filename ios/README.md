# Nice 视频 — VLC 原生离线版

SwiftUI + **MobileVLCKit 3.7.3**，对接仓库 `videos/` 的列表和下载 API。
**可直接打开 iPhone「文件」中的视频，也可下载服务器影片后离线观看。**

## 在 Mac 上运行

```bash
# 在仓库根目录
brew install xcodegen cocoapods
bash ios/setup.sh
open ios/NiceVideos.xcworkspace
```

要求：Xcode 15+、iOS 17+。安装依赖需要外网；App 播放本地文件不需要外网。

**CocoaPods 接入后必须打开 `.xcworkspace`，不再使用 `.xcodeproj` 运行。**
在 `NiceVideos` target 的 Signing & Capabilities 选择自己的 Team。默认 Bundle Identifier 仍是
`com.anxiong.nicevideos`，与第一版保持一致。已安装旧版时不要卸载；保持原标识和签名更新，
旧的 Media 文件、v1 下载索引、`position.<id>` 播放位置会继续使用。
若以前改过标识或 Team，应在 `project.yml` 保留相同配置，避免重新生成工程后变回默认值。

App 默认打开「本地」，可直接点「打开文件」选择影片。首次从服务器下载：设置 → `http://192.168.19.70:8106` → 添加 → 连接 → 服务器 → 下载。
地址只是用户当前局域网示例，可修改；真机不要填 localhost。允许系统首次提示的局域网权限。
后端仍然这样运行，无需改接口：

```bash
cd videos
PORT=8106 go run .
```

### 从 iPhone「文件」直接播放视频

从 1.2.0（构建 5）开始，在「本地」点「打开文件」→「浏览」，选「我的 iPhone」、iCloud 云盘或系统「文件」能看到的外接存储、网盘位置，再点选影片。即使下载列表为空也可以打开文件。左右格式影片进入播放器后同样可以点「VR」。

- 1.2.3（构建 8）从「文件」打开 MP4、MOV 或 M4V 时优先使用 iOS 系统播放器，普通播放直接显示系统视频图层。进入左右分屏时从同一播放器按显示时间取帧。播放器按需从已打开的文件分块读取。系统解码报告失败或播放时间持续前进却没有输出首帧时，会尝试 VLC。点「VR」可查看当前解码方式，也可在普通或 VR 播放时手动切换。其他文件格式沿用 VLC，已下载片库仍默认使用 VLC 原生显示。
- 1.2.1（构建 6）修复了文件时间戳或同名缓存更新后误报读取失败的问题。播放器继续读取已打开的原文件。遇到真实读取错误时会显示原因、系统错误码及读取位置。
- 手机或外接盘上已有的影片直接从原位置只读播放。Nice 视频按需分块读取，支持超过 3 GB 的文件，无需同等容量的导入空间。用外接盘看片时请保持连接。
- 只有云端副本时，iCloud 或网盘可能先下载、缓存整部影片，需要相应的本机空间。若打算断网看，先在「文件」中将影片下载到设备。
- 选中的文件单独播放，退出后仍在原位置。下次通过「打开文件」重新选择。下载片库的批量删除不会处理这些外部文件。

### 在 iPhone 上看 VR 影片（1.3.7，构建 18）

1. 打开底部的「VR」，点「选择文件夹」，在系统「文件」中选中影片所在目录。点子文件夹可以继续浏览，点影片直接进入全景播放。列表显示文件名、大小和格式，已经在本地的影片会按需读取缩略图、时长和分辨率。App 会记住已授权的文件夹，也可以从「VR」只打开一个视频。文件夹只读，影片从原位置按需读取。首次按 180° 经纬全景、左右分屏、手机单屏观看处理。
   原「本地 → 打开文件」仍先进入普通播放，可在播放器中点「VR → 进入全景 VR」。
2. 单指拖动画面可环顾，双指缩放，双击默认回正。进入「VR 设置」可以选择 360°、180° 圆形等距鱼眼或平面影院，指定左右、上下或单画面，横放进手机眼镜时选择双眼。常规平面 3D 影片也可直接使用原有的半宽／全宽 SBS 入口。
3. 流畅画质把 VR 最终绘制的最长边限制到 1920 像素，屏幕原生画质则按显示屏尺寸绘制。解码器仍须解码原片；AVPlayer 分屏取帧和 VLC 内存帧的最长边目标为 2560 像素。设置不会改写影片。眼镜使用通用 Cardboard v1 镜片参数。
4. 可选择是否启用陀螺仪，设置双击动作和缩放灵敏度。戴上手机眼镜并开启陀螺仪后，在「VR 设置 → 环顾 → 头部唤出控制栏」选择连续点头两次，或看向左上／右上并停稳约一秒。此功能默认关闭。在 VR 播放时，兼容的扩展手柄可用 A 键播放／暂停、X 回正、Y 显示／隐藏控制栏、左右肩键回退／快进 15 秒。
5. 拖动视角仅更新 Metal 画面；拖动进度条只预览目标时间，松手后跳转一次，取消时保留原播放位置。从下载片库或「文件」打开受支持的 MP4、MOV、M4V 时，平面与全景共用一个 AVPlayerItem。播放中更换解码器或切换 VLC 原生／兼容输出会按原进度重新打开影片。使用 VLC 兼容显示时，每次重新打开影片或播完重播都会建立新的视频帧输出。

要覆盖自己的旧版，请在 Mac 上保留原有签名 Team 和 Bundle Identifier，拉取改动后运行 `bash ios/setup.sh`，打开 `ios/NiceVideos.xcworkspace`，选中 iPhone 并运行。CI 的 `NiceVideos-iPhone-unsigned` 包含已编译的 arm64 真机 IPA，须由使用者签名后安装。

### 内置 Afterglow XR 视频播放

在底部「VR」点「预设」可以先选投影、片源排布、手机单屏或双眼、陀螺仪、视场角、渲染比例和显示帧率。默认使用 360°、左右分屏、双眼、75% 渲染和 30 fps 显示。点「Afterglow XR 播放」从「文件」打开原片。在已授权的 VR 目录可点影片旁的眼镜按钮，从下载片库可在影片菜单选择「用 Afterglow XR 播放」。正在普通或平面 SBS 播放的影片可点控制栏的「Afterglow XR」，在全景中可从「VR 设置 → 片源信息」切换。

此入口移植了 [Afterglow 的普通拼接视频取帧实现](https://github.com/blaineam/Afterglow/blob/fac3236d61b3196846c63fc4bcc4188da4691142/app/Afterglow/Media/VideoPlayer.swift)，在 NiceVideos 内直接把解出的同一帧交给 Metal 按左右眼投影。许可证和改动说明随 App 提供。原文件按需读取。投影时只保留所需的视频输出；首次请求最长边 1920，适用的 SDR 素材使用双平面缓冲。默认按 30 Hz 取帧并绘制；选择 60 fps 会同时调整取帧与绘制目标，源视频仍按原编码解码。系统视频轨标记不可解码时，这个入口会尝试实际取帧；若打开失败或前台播放等不到首帧，会按当前进度尝试 VLC。

完整 8K 全景（长边至少 7680、短边至少 3840）走 VLC 全景取帧时，第一轮协商就将输出最长边限制到 1600。持续丢帧并满足恢复条件时，再尝试一次最长边 1280。长片可在同一位置连续播放 20–30 秒，再从「VR 设置」复制诊断，对照实际的 `route`、`loadID`、`buffer`、`copied` 和 `presentID`。这些尺寸和显示选项减少取帧、转换或绘制的工作量，原片的 8K HEVC 解码负担仍取决于编码参数和设备。

### 在 iPhone 上定位进度前进、画面静止或黑屏

当 Afterglow 取不到视频帧，VLC 又在最低输出分辨率只交付一张图时，减少 Metal 的绘制比例不能减轻原片的 8K 解码负担。「VR」页的「制作兼容副本」可以在手机上选择本地 SDR 左右分屏原片和保存文件夹，单独转换为较小的 H.264 MP4。8192×4096 的片源输出为 1920×960、30 fps，两眼保留在同一画面中。请先选择短片验证；完整影片耗时取决于设备、存储和片源。有足够空间时再处理长片。已完成的副本可直接用 Afterglow 打开。Mac 上制作 4K 副本的方法见下文。

Afterglow 遇到系统标记为不可解码的片源时，仍会尝试取帧。前台实际播放累计约 4 秒仍无首帧时，会保留最新进度并转入 VLC。在该输入上拖进度或重连视频输出也会计入启动等待。在暂停和切后台期间不累计时间。VLC 处理高帧率全景时，除了完全停止出图，也能识别持续重度丢帧、每秒只交出少数画面的情况，最多再降低一次输出尺寸。

点「复制播放诊断」时会抽样当前保留画面和用同一着色器离屏重绘的画面。报告按眼记录亮度的最小值／均值／最大值。若 `matchesCurrentInput=no`，这些数值属于先前输入。抽样仅用于定位，无法测量 iPhone 屏幕的实际亮度。报告不包含图像。

对于 8K SDR 长片，可以在装有 FFmpeg 的 Mac 上抽取故障位置的 30 秒，比较 4K AVC 与保留原编码的两个片段。以下命令会弹出文件选择窗口，输出写到「影片」下新建的文件夹。把 `--start` 换成实际出错时间。若兼容片段在手机上播放正常，可单独传 `--full` 转换整片。

```bash
bash ios/tools/vr-compatible-copy.sh --start 00:09:28 --source-sample
```

1. 用原片和出问题的投影模式播放，时间继续走动时先等约 20 秒，保持 App 在前台。点「VR 设置 → 复制播放诊断」即可粘贴整份报告；普通模式下从播放器的「VR」菜单复制。报告按会话保留一段采样历史，包含版本、设备、视频轨和实际出帧情况。
2. 如需连续日志，在 Mac 的仓库运行 `bash ios/setup.sh`，打开 `ios/NiceVideos.xcworkspace`，选择 scheme `NiceVideos` 和已连接的 iPhone，按 ⌘R。在 Xcode 按 ⇧⌘Y 显示调试区，在控制台筛选 `[NiceVR]`。从打开原片起录到故障出现后约 20 秒，复制同一个 `session=` 的记录。可以一并说明当时声音是否连续、文件在手机／外接盘／网盘哪一处，以及退出全景使用普通播放是否恢复画面。
3. 对比相隔约 5 秒的几条记录。`media` 是播放时钟，系统解码路径另有 `framePTS` 和 `copied`。在 Metal 渲染器中，`recvID`、`acceptID`、`submitID`、`completeID`、`presentID` 分别反映收到、可绘制、提交、GPU 完成和收到屏幕呈现回调的最新帧。普通系统图层不经过这条 Metal 路径。收到呈现回调也不能判断两帧的实际像素或原片内容是否相同。
4. 测几秒钟的短片时，让影片自然播完，在同一播放页点重播。选一个明显运动的物体，对比首播和重播；在第二轮还在播放时复制诊断。VLC 路径可对照每次打开的输入编号，以及同一轮的 `offered`、`delivered` 和 Metal 的 `recvID`、`presentID`。
5. 长片首播若只有一帧上屏，可以先保持同一片段播放约 15 秒，然后复制诊断。用 `track` 查看源视频轨，用 `buffer` 查看交给 Metal 的画面尺寸，`target` 表示最终屏幕绘制尺寸。在 VLC 兼容模式里，如果已交付首帧后持续丢画面，播放器可从当前进度尝试一次较低分辨率的视频输出，恢复事件和新一轮的 `loadID` 会出现在同一份诊断里。
6. 如有原片的 Mac 副本，下面的命令只输出第一条视频轨的媒体参数。将最后一个参数换为实际文件路径。

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,profile,level,width,height,pix_fmt,avg_frame_rate,color_space,color_transfer,color_primaries,bit_rate:format=duration,size,bit_rate \
  -of json "/path/to/video.mp4"
```

技术参考：[GPUImage 的 AVPlayerItemVideoOutput 取帧实现](https://github.com/BradLarson/GPUImage/blob/master/framework/Source/GPUImageMovie.m)、[Apple 的视频输出通知说明](https://developer.apple.com/documentation/avfoundation/avplayeritemvideooutput/requestnotificationofmediadatachange(withadvanceinterval:))、[VideoLAN 的内存帧回调及性能说明](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html)。

### 管理服务器地址

- 打开设置时，地址框预填当前连接；没有当前连接时使用最后保存的地址。
- 可直接修改 IP 或端口后点「添加」。成功后保留规范化后的完整链接并收起键盘；键盘「完成」也可提交。
- 点击某个地址的「连接」后，输入框会同步为该地址。重复添加相同地址不会新增一行。
- 每行的「删除」会先要求确认，只移除保存的地址。删除当前地址会清空连接和当前列表，之后可手动连接其他地址；重启不会恢复已删除的地址。
- 删除地址不删除服务器文件或手机视频，不清除收藏、观看标记和播放进度，也不中断已有下载。

### 清理已经下载的视频

在「服务器」页点击「一键删除已经下载的视频」后立即开始，无需再次确认。
它处理当前服务器中已完整下载到手机的视频源文件，保留手机本地副本、收藏和标记。
执行中显示处理进度并禁止重复启动，完成后显示成功、跳过及失败数量；每次删除前仍会
检查下载记录和本地文件，已切换服务器或本地副本缺失的项目会跳过。

### 筛选列表与顺序连播

- 「本地」和「服务器」列表顶部可选择「全部 / 收藏 / 未看」，并与文件名搜索一起使用。
  「未看」沿用现有观看标记：视频成功开始播放并输出画面后便标记为已观看，不要求播到结尾。
- 点击一个视频时，按当前筛选和搜索结果的显示顺序建立本次播放列表，从点击的那一条开始播放，
  自然播完后自动播放后面的条目；最后一条播完后停止，不循环回第一条。
- 本地列表保持原有下载完成时间排序；服务器列表保持当前服务器的显示顺序，播放队列只纳入
  其中已经下载完成的手机副本，未下载的视频仍须先下载。
- 播放列表在打开播放器时固定。播放中标记已看、收藏或取消收藏、完成新下载，都不会插队或
  改变本次播放顺序；关闭播放器后重新点击列表，才按最新结果建立新队列。
- 上一个、下一个和播放器内的列表选择共用这一队列。文件缺失或无效时按顺序跳过，
  不会改用网络播放。暂停、退出或切到后台会取消待处理的自动连播。
- 按住进度条拖动时会等待手势结束再决定是否连播；即使拖动期间已经播到结尾，往回拖后
  仍在当前视频应用所选位置，原本暂停的播放也不会因此自动发声。

## 行为与边界

- 只有用户主动连接服务器或点击刷新才请求 `/api/videos`；添加地址和冷启动不刷新、不检测登录或网络。
- 下载使用 API 返回的 `/api/download/...`，单个文件独立任务；批量下载不使用 ZIP。
- 不创建 `/api/stream/...` 播放请求。服务器返回的 `url` 仅为 API 兼容保留，不参与播放。
- 本地页独立于服务器设置/缓存/下载任务恢复，断网启动也能进入。
- 请求构造、下载索引和 VLC 入口分别检查本地文件；文件缺失时明确报错，绝不回退网络。
- HTTP 状态、响应类型、文件大小检查通过后同步移动到 Application Support，再原子保存索引。
  下载的错误文本和常见伪装播放清单会被拒绝。大小与头部检查不等于完整解码或密码学校验。
- VLC 提供播放/暂停、进度条、前后 15 秒；位置定期保存，关闭/暂停时保存，播完清除旧位置。
- 全屏页面支持系统横竖屏；锁屏/切后台/来电/拔出耳机时暂停，返回不自动发声。
- 重复视图更新不会重复启动；关闭时停止原生输出、解除 drawable/delegate，并丢弃晚到事件。
- 默认禁止新下载使用蜂窝数据，可在设置打开。已有任务的网络策略需取消重试后才改变。

当前允许下载 MP4/M4V/MOV/MKV/AVI/WebM/OGG/FLV/WMV/TS 完整文件；容器白名单不保证所有编码、
配置档次、码率或损坏文件可播放。HLS/DASH、M3U/PLS 等清单不支持离线下载，也不提供在线回退。
没有实现外部字幕下载/音轨字幕选择、倍速、画中画、后台音频、断点续传、空间配额。
失败/取消后重试是重新完整下载；iOS 手动上划强退会中止后台传输，不承诺强退后继续下载。

这些测试不等于物理设备端到端验收，尤其不能证明所有编码、音频输出、锁屏和后台下载都正常。
源码生成环境没有 Xcode/iOS SDK；编译/测试实际状态以该提交的 macOS CI 为准。

## 合并前真机验收

| 场景 | 必须达到的结果 |
|---|---|
| 下载真实 MP4、MKV，检查画面与声音 | 本地文件可播放，拖动进度正常 |
| 飞行模式并关闭 Wi-Fi → 强退 → 冷启动 | 立即进入本地页，可播放已下载文件 |
| 关闭 Go 服务/删除服务器原文件/清空服务器设置 | 手机原副本仍可播放 |
| 连续打开、关闭、切换视频 | 旧视频声音和播放资源不残留 |
| 播放中锁屏、来电、拔出耳机 | 暂停，返回后用户手动继续 |
| 下载中断/空间不足/同名文件变更/HTML错误页 | 明确失败，不伪装完整下载 |
| 安装前一版并下载，再覆盖安装新版 | 原下载和进度保留（不卸载，不改变 Bundle ID） |
| 删除手机副本 | 不向服务器发送删除请求 |

## 主要文件

`OfflineMediaPolicy.swift` 是无框架依赖的本地播放边界；`Core.swift` 保存原有数据协议和索引；
`VideoStore.swift` 只负责列表、下载和本地请求；`VLCPlaybackEngine.swift` 封装固定版本 VLC；
`PlaybackScreen.swift` 管理播放状态/生命周期；`Views.swift` 默认展示本地库。

服务器仍无鉴权，不要把 8106 直接暴露公网。后端没有稳定版本/hash，同名同大小替换无法自动检测。
