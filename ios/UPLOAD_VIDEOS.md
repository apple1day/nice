# 上传 App 本地视频到服务器

## 操作

1. 在「设置」填写本次要上传到的服务器根地址，例如 `http://192.168.19.70:8106`。
   上传目标是此配置，不是视频最初下载来源；不同来源的本地视频可上传到同一目标。
2. 底部新增「上传」页面 →「选择本地视频上传」。可以搜索、单选或多选；全选只针对可见结果。
3. 核对确认框中的服务器地址和数量，确认后逐个上传。在「上传」查看进度、取消、重试。
4. 上传队列结束后，有成功上传且当前服务器仍是目标时，自动刷新服务器列表一次。

此版为**前台上传**，不是系统后台传输：大视频请保持 App 在前台，锁屏/切后台/强退不保证继续。
失败重试从头发送；App 重启后不自动重发未确认任务，需用户检查服务器列表后手动重试。
发送 100% 只代表字节已发出，收到匹配的服务器确认后才显示「已上传」。
本版只上传 App 已下载的视频，不包含相册、系统文件导入或跨设备同步收藏/观看状态。

## 保留现有数据

- 上传是复制到服务器，不移动/删除手机文件，不修改下载索引、收藏、观看标记或待删除队列。
- 固定使用确认时的目标地址和蜂窝设置；拒绝 HTTP 重定向，不把文件发送到另一地址。
- 默认禁用蜂窝数据；上传页面可开启，仅影响之后创建的任务。
- 同名服务器文件/目录/符号链接返回 409，显示「同名未上传」，不覆盖。
- 取消不撤销已经在服务器提交的文件；响应丢失时结果可能不确定，请核对列表，不能凭同名/同大小冒充成功。
- 进行中的文件使用本机硬链接快照；如果此时删除本地列表项，原数据块会保持到上传结束释放快照。
  上传程序不把整段视频读入 Data、不打 ZIP、不复制整段视频作为表单；系统网络实现仍可能使用自己的缓冲。
- 排队只保存小体积元数据，轮到该项才核对下载批次和目标文件，不扫描整个本地库。
- 上传进度只刷新独立进度对象，不发布 VideoStore 的下载记录/进度；已有播放性能优化保留。

## 必须同时更新服务器

新增 `POST /api/upload-file?name=<百分号编码的原文件名>`，不能仅更新 App。
在**服务器机器**的 nice 仓库拉取相同分支，停掉旧 Go 服务，再用原来的环境变量/.env 启动：

```bash
git fetch origin && git switch v1.2_batch_delete && git pull --ff-only origin v1.2_batch_delete
cd videos
go run .
```

保留现有 VIDEO_DIR/DATA_DIR/PORT 配置；不是改为新的空视频目录。通过进程管理器部署时，按原方式重新构建并重启。
使用 `go run .` 或 `go build .`，不要只编译 `main.go`，新增 handler 在独立 Go 文件中。
旧网页的 multipart `/api/upload` 接口保持原样，这次的“不覆盖”保障仅适用于新的 App 上传接口。
后端仍无登录鉴权，仅用于可信局域网，不应直接暴露公网。

新接口使用原始文件体，单文件上限 20 GiB，最多同时接收两个写入请求；App 队列只发送一个。
服务器流式写 `.nice-upload-*.part`，检查实际长度后在同一文件系统通过硬链接原子发布；不会覆盖已有目标。
该文件系统必须支持硬链接；若服务进程异常崩溃，可能遗留 `.part` 文件，它们不进入视频列表。
正常请求结束或连接中断会清理临时文件。代理部署还需配置上传体积和超时限制，不要重定向上传地址。

请求头：Content-Type: application/octet-stream、X-Nice-Upload-ID: UUID、X-Nice-Upload-Bytes: 字节数。
成功为 HTTP 201，JSON 包含 version=1、uploadID、name、size；App 全部核对后才标记成功。
HEAD 同一路径可检查文件名是否可用（204），同名返回409；可用响应包含 X-Nice-Upload-Version: 1。


## 验证

```bash
bash ios/check-upload.sh
python3 -m unittest discover -s ios/tools -p test_upload_hot_path.py -v
# 服务器目录中，使用测试专属的 VIDEO_DIR / STATIC_DIR / DATA_DIR：
go test -race ./...
# Mac 上运行完整 App 测试：
bash ios/test.sh
```

覆盖名称编码、收据和大小验证、禁止覆盖/重定向、快照存续与清理、串行队列、重复提交、来源变化、
恢复后不自动重传，以及服务器并发重名/短文件/超长文件/中断清理。模拟响应测试不等于 iPhone 网络实测。
真机重点验证：上传一个服务器不存在的 MP4 → 刷新服务器并播放；上传多个和取消；目标切换；中文/+/%/#名称；
同名视频不覆盖；手机低空间/服务器空间不足；锁屏中断后手动重试；收藏、观看标记和本地文件仍保留。
