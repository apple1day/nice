# 全屏与自动隐藏播放控制

基于 `v1.1_watch_delete`，保持 VLC 本地播放及三项待删除队列。

## 操作

- 画面底部右侧的放大图标进入全屏；再点缩小图标退出全屏。
- 全屏隐藏导航标题栏和状态栏，视频区域延伸到屏幕边缘。底部控制和关闭按钮仍避开安全区域。
- 全屏与横屏不同：本版不强制旋转或锁定方向，横竖屏跟随设备和系统方向设置；按原始比例显示，不强行拉伸或裁切。
- 进度条覆盖在视频画面底部，显示当前位置/总时长，支持拖动、前后 15 秒、播放/暂停。
- 真正开始播放后，默认 **4 秒无操作**淡出控制层；包括进度条、播放/全屏按钮及中央待删除按钮，不留遮挡画面的底部栏。
- 轻点画面空白处重新显示，再无操作 4 秒后隐藏；控制已显示且正在播放时，轻点空白处也可立即隐藏。
- 暂停、打开文件、结束、错误提示、拖动进度期间保持显示。松开进度条或点击操作后重新计时。
- 切后台取消计时并沿用原来的暂停策略；返回后需用户手动继续。VoiceOver 开启时不自动隐藏。
- 中央删除按钮只有显示时可点，隐藏时不接收点击；第一下唤醒控制层不会误删除。队列规则和本地文件删除逻辑不变。

## 实现边界

`PlaybackControlsState` 用单调时间表示下一次隐藏期限；只在交互/播放状态切换时重置，
不会被不断前进的播放时间重置。SwiftUI `.task(id:)` 在期限变化和页面关闭时取消旧任务，
状态层再次检查期限，拒绝迟到回调。

播放器一直持有同一个 `PlaybackModel` 和同一结构位置的 `VLCVideoSurface`。
切全屏只改变安全区域和导航栏，不另开播放器、不改变 media、不调用 close、不释放正在播放文件的删除保护。
中央删除按钮在短屏/横屏用紧凑布局，按钮与画面唤醒层是兄弟视图，避免事件同时触发。

## 验证

```bash
# 相同 XCTest 源码在临时 Swift Package 中执行，不依赖 CocoaPods 或视频
bash ios/check-player-controls.sh
# 包含所有离线/删除/VLC 解码回归的 iOS 模拟器测试
bash ios/test.sh
```

新增 20 项确定性状态测试：首次显示、4秒边界、点击唤醒、立即隐藏、交互延期、旧任务失效、
播放时间更新不延期、暂停/续播、拖动/松开、暂停拖动、全屏来回切换、后台/返回、VoiceOver、
错误弹窗、关闭后回调、非法延时参数。测试不等待真实4秒。

这些状态测试不能代替触控/视频渲染验收。合并前目标 iPhone 应测试：
1. 播放后等待4秒，进度/按钮消失；轻点画面恢复；第一下唤醒不执行删除。
2. 拖动超过4秒仍能操作，暂停保持显示；恢复播放重新计时。
3. 来回切全屏和旋转设备，不从头播放、不丢声音、不释放待删除保护；留意刘海/Home指示条。
4. 全屏中标记第4个视频，只删除最早副本；退出全屏/关闭再做一键清理。
5. 飞行模式冷启动/播放仍然可用，后台恢复不自动发声，退出后没有旧计时或旧音频残留。

实际编译/模拟器/设备SDK验证以当前提交的 CI 为准，设备SDK编译不等于目标真机触控已通过。
